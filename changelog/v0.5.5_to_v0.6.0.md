# HPD Agent 0.5.5 To 0.6.0

## Progressive Skills

Skills now use `Skill.Create(...)` and structured capabilities. The pre-release `SkillFactory`, positional string references, and generated-skill reflection fallback were removed without a compatibility layer.

```csharp
[Skill]
public static Skill DataAnalysis() => Skill.Create(
    name: "data_analysis",
    description: "Helps validate and analyze datasets.",
    instructions: SkillInstructions.FromText(
        "Validate the dataset before analysis."),
    capabilities:
    [
        SkillCapabilities.Function<DataTools>(nameof(ValidateDataset)),
        SkillCapabilities.Resource(
            "read_validation_guide",
            "Reads the dataset validation requirements.",
            "Every row must have a unique identifier.")
    ]);
```

Before activation, the model sees only the skill name and discovery description. Activation returns the detailed instructions and reveals the skill's referenced functions, resources, and compatible external scripts for the message turn.

Runtime skills can be loaded from `SKILL.md` directories or installed through `ISkillStore`. Managed packages are attached explicitly to an owning harness with `AddSkillsFromStore(...)`. Watchable sources support validated hot reload with last-known-good retention.

`AddHPDSkills()` supplies replacement-safe in-memory DI defaults. Replace `IContentStore` for durable package storage, or supply a custom `ISkillStore` through DI or `WithSkillStore(...)`.

See [Skills Overview](../guides/skills/overview.md) for the current API and migration examples.

## Atomic Runtime Process Execution Binding

Agent-facing process tools no longer resolve a standalone `IProcessProvider` from runtime
capabilities. Runtimes publish one `RuntimeProcessExecutionBinding` that atomically pairs:

- environment identity and revision;
- the process provider;
- the optional environment runtime facade;
- the authorized `TargetHandle<ExecutionUnit>`.

The provider-only compatibility path and tool-created local targets were removed. Custom sandbox or
environment middleware must publish the complete binding. If it cannot provide a valid execution
target, it must leave the capability absent; process-backed tools then fail closed instead of running
on the host or combining mismatched authorities.

`WithLocalSandbox()` already publishes the complete local binding. See
[Local Process Isolation](../guides/sandboxing/local-process-isolation.md) for the current contract.
